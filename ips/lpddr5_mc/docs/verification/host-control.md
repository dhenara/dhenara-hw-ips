# Host and control verification

This page records owning RTL checks for the host/control contribution. Combined controller qualification remains governed by the [canonical contracts](../spec/contracts.md).

## Run the owning checks

After [preparing the pinned tools](contracts.md), run the [aggregate entry point](../../dv/host/check.py) from the repository root. Use a fresh report path for each run:

```sh
python3 ips/lpddr5_mc/dv/host/check.py \
  --build-subdir host-committed \
  --report ips/lpddr5_mc/dv/host/out/committed/summary.json
```

Add `--dry-run` to print the literal phase commands and deadlines without executing checks or writing reports. The aggregate runs its own failure-handling tests, the existing foundation `Makefile` check, static parameter admission, CDC transports, APB/control-link checks, register/channel adapters, four representative host-core configurations, the full AXI bridge fixture matrix, assembled-host behavior, the independent lease/source-order oracle and warning-fatal assembly elaboration. All phases run serially so compiler processes do not compete for the same sandbox memory.

The core behavior configurations are strict 64-bit/depth-16, 128-bit/depth-16 and 256-bit/depth-64, plus early-posted 128-bit/depth-16. Their testbench uses two ports and two channels to retain overlap and ordering checks. Root `lpddr5_mc_host` lint uses minimum `(ports=1, channels=1, ranks=1, data=64, ID=4, address=32, depth=16)`, the source defaults, and maximum `(2, 2, 2, 256, 16, 40, 64)`. These representative variants and boundary checks do not cover the Cartesian product of all supported parameters. Root elaboration does not establish combined host/channel behavior.

Compiler output, captured simulator sources and Python caches remain below `DHENARA_AGENT_TOOL_STORAGE_ROOT`. The aggregate report and a sibling `<report-stem>-phases/` directory retain phase reports and logs under `dv/host/out/`. Every phase has a finite deadline: runner and Python checks 30 seconds each, root elaboration 120 seconds each, static parameters and AXI matrix 600 seconds each, foundation 300 seconds, and transport/core/assembly/lease phases 900 seconds each. A timeout kills that phase's compiler/simulator process group, records its actual signal exit and makes the aggregate exit 124. Other failures preserve their exit status; later phases are marked `not_run`. A child process exiting zero without its required valid report fails the aggregate.

The aggregate records the complete tracked and nonignored source-file inventory, hashes, Git revision and dirty state before and after execution. A source change or a different revision invalidates the aggregate result. Reports are immutable by convention: an existing report or phase directory is rejected, and reruns require a new report path. Dirty-tree runs remain development evidence. Delivery evidence requires a separate run on the exact clean committed contribution.

## Evidence and limits

Each report identifies the exact source it checked. `source_dirty=true` marks development evidence; delivery requires a complete aggregate on a clean commit and a separate clean checkout with isolated build output. Preserve unsuccessful runs and their logs when correcting a failure. A later passing report applies to its own manifest and does not change earlier results.

The contribution checks host/control behavior against independent behavioral channel completion and memory witnesses. Channel scheduling, pin timing, ECC implementation, connected FSP transitions and the combined 100-period throughput criterion require the reconciled controller and its independent system environment. No synthesis, physical timing, metastability, vendor-PHY interoperability, fresh-host installation or remote-CI qualification is established by these checks.

## Common-domain core and simulator qualification

The [parameter runner](../../dv/host/parameter_run.py) checks the canonical static descriptor across all supported ports/channels/ranks, data/ID/address widths, depths, service divisions, WCK ratios and read/write/raw-parity capability combinations. It requires 176904 admitted descriptors, 227448 rejected link combinations and 30 invalid single-field boundaries/holes. A separate reset-held production-core fixture admits minimum/maximum structural settings and requires the core's actual initial assertion for unsupported nonzero counts, widths and queue sizes. Compiler failure or an arbitrary crash fails the runner. Expected assertion exits and their original logs are retained separately from commands that must exit zero. Zero structural dimensions are checked in the descriptor matrix; negative-width RTL arrays are not elaborated. Static admission does not exercise data traffic or replace the [connected parameter checks](system.md#actual-rtl-binding). Run with fresh report and build names:

```sh
python3 ips/lpddr5_mc/dv/host/parameter_run.py \
  --report "$PWD/ips/lpddr5_mc/evidence/parameter-admission/report.json" \
  --build-name parameter-admission
```

The [core runner](../../dv/host/core_run.py) captures its package, contracts, core RTL, testbench and runner before compilation and rejects a source change during the run. It retains the observed `CORE_RESULT` family count and requires every family expected by its current fixture. It also runs minimum/maximum core elaboration. Its independent byte-memory responder verifies host behavior within one common clock domain; asynchronous AXI admission and real channel pin/ECC behavior need their separate checks.

The qualified Verilator 5.006 core simulation requires `--public-flat-rw`, which `core_run.py` supplies. A retained minimal reproducer showed a task-written packed slot changing from 0 to 1 while its derived combinational slot remained 0 without that option; the same source with the option produced matching 0/1/2 values and `SENSITIVITY PASS`. This option keeps task-driven packed writes visible to the simulator's combinational scheduling. Diagnostic logs are retained as `dv/host/out/core/sensitivity-2-run.log` and `sensitivity-public-run.log`. Keep the remedy when reproducing this qualified tool version; qualify another simulator version independently.

## APB and channel adapters

The [APB runner](../../dv/host/apb_run.py) checks generated metadata consistency, schema-derived register access, strobes, locks, command sequencing, IRQ/W1C behavior, immutable prepare/commit snapshots, stale/partial/timeout acknowledgement handling and status/first-error snapshots. It exercises the actual configuration/command/acknowledgement/status mailboxes on independent clocks, checks minimum/maximum APB parameters and compiles the C11 programming example. The APB fixture clears an error event, repeatedly transfers ordinary zero-event snapshots, and checks no IRQ relatch, counter increment or detail replacement; a later same-bit notification must increment once and capture its new detail. Channel-side numeric-profile validation, notification production and live drain witnesses remain integration responsibilities.

The [adapter runner](../../dv/host/adapter_run.py) compares committed register-image decoding and mapping with canonical Python oracle vectors. Cases cover all 16 QoS classes, port limits, modes/epochs, 40-bit boundaries, region holes and unsorted permutations, ECC capacity and rank boundaries, one/two channels and eight regions. Real channel-link queues compare complete request, completion and response-feedback payloads at actual handshakes. Reset tests account for aborted transport records and require explicit two-sided rearm with fresh epochs; acceptance-ledger settlement remains the host owner's responsibility.

## CDC transports

The [explicit source list](../../rtl/cdc/files.f) contains the synchronizer, reset fence, asynchronous FIFO and bundled mailbox. Run their independent-clock RTL tests from the repository root after the [pinned tool preparation](contracts.md):

```sh
python3 ips/lpddr5_mc/dv/host/cdc_check.py \
  --report /absolute/path/to/evidence/cdc.json
```

Disposable compilation output is placed below `DHENARA_AGENT_TOOL_STORAGE_ROOT/host-cdc`. The report records source hashes, Git revision/dirty state, simulator version, literal commands, durations, seed 2095 and logs. A dirty-tree run is development evidence. The final contribution must rerun on its committed source and preserve that report separately.

The testbench compares every accepted transport payload against independent queues and checks VALID/data stability under backpressure. It exercises depth 2/16/64, widths 1/80/1024, independently phased 6/10-ns and 10/4-ns clocks, full capacity, pointer wrap, enable gating, random receiver stalls, mailbox acknowledgement delay, destination reset while its clock is stopped, one-sided rearm rejection and source reset. It explicitly accounts aborted entries separately from consumed entries and checks that old payload/toggle state cannot reappear after rearm.

Reset at either endpoint asynchronously aborts both transport ends and latches faults. Startup is also faulted. The two sides stay blocked until each owner supplies a domain-local rearm pulse after every actual local transport reset-ready witness, host settlement or coordinated host reset, and fresh boot/configuration identities. FIFO and mailbox readiness outputs are the owning fence reset releases; they remain low when a reset endpoint clock is stopped. The regression rejects a pulse before those releases, checks that one-sided rearm cannot reopen transport, and requires a new valid pulse after readiness. The AXI endpoint retains an initialization request until all ten source transport ends can accept rearm; the bridge waits for all core transport ends, and initialization completes only after the matching acknowledgement and cleared fault observations. Bridge rearm readiness also waits for the fresh disable handshake and all descriptor imports. Healthy epoch replacement waits for actual source retirement and empty ledger entries before resetting generations; faulted recovery uses the surviving host-handshake ledger because the old retirement queues were aborted. The owning AXI fixture stalls real retirement consumption across a healthy boot change and verifies that old configuration/generations remain until consumption, then checks fresh successful traffic. An attempted rearm immediately after enable falls is rejected while the fresh disable exchange is pending. A continuously high rearm input would bypass this recovery permission and is unsupported. FIFO storage alone cannot reconstruct accepted AXI beat counts after transport reset; the host must retain that ledger outside the aborted transport or coordinate the host reset explicitly. Configuration mailboxes must be discarded and rebuilt from the new epoch.

The FIFOs synchronize only Gray publication pointers. The mailbox holds one immutable source payload until its destination consumes it and the acknowledgement returns. Read/write enable inputs are local clock-domain controls. The [physical integration requirements](../../constraints/host/README.md) describe pointer skew, bundled-data timing and reset constraints. Digital simulation does not prove metastability mean time between failures or replace combined-netlist CDC/reset analysis.

## Asynchronous AXI endpoints

Run the bridge's real independent-clock simulations from the repository root:

```sh
python3 ips/lpddr5_mc/dv/host/axi_run.py \
  --report /absolute/path/to/evidence/axi.json
```

The runner uses the [bridge source list](../../rtl/host/axi-files.f), assertion-enabled warning-fatal Verilator 5.006 and its `--public-flat-rw` scheduling workaround. The simulated AXI clocks both run at 400 MHz with a 0.375 ns phase offset; the host transport clock runs at 800 MHz. Four configurations exercise data widths 64/128/256, depths 16/32/64, ID widths 4/8/16 and address widths 32/36/40. Repeated narrow IDs exercise source response order. `--default-only` runs the 128-bit/depth-16 development case. Reports retain exact source hashes, dirty state, literal commands, timings and every simulator log. A successful compile alone does not produce a passing report: every selected simulation must emit its completion witness.

The fixture independently records actual source AW/AR handshakes and checks complete imported address payloads, per-source sequence order and reserved slot/generation. Earlier unimported records from another source must be disjoint before a younger import can pass them; simultaneous disjoint imports are allowed. It samples actual source R/B handshakes, verifies IDs, read payloads, RLAST and complete response counts, and checks held response stability. The core-side consumer models finite per-slot credits and explicit retirement after real source feedback. Tests cover delayed W, concurrent ports and directions, stale-boot rejection, core reset, peer reset, pending W consumption, remaining read beats, preserved exposed responses, and a fresh successful transaction after recovery.

Quiesce is a handshake across admission ownership. `admission_busy_o` stays set until the coordinator has completed its pending control exchange and each source has acknowledged this exact disable request token with both synchronized enable stages zero, no remaining candidate or published miss request, no pending control acknowledgement, and every accepted descriptor consumed by the core. The acceptance FIFO exports its writer-local pending witness from the local publication pointer and synchronized actual reader-consumption pointer; a fresh source disable acknowledgement waits for that witness to clear. A prolonged core address-import stall explicitly tests this gate. Core-side FIFO visibility alone is insufficient at arbitrary clock ratios. A falling enable fences admission immediately, before the next core edge publishes the token. The stopped-source test applies a one-core-cycle enable pulse and requires a fresh acknowledgement after the source clocks restart; an old idle level cannot satisfy it. Repeated disable generations serialize: the coordinator waits for every acknowledgement of the previous request before toggling again, so a stopped clock cannot alias two outstanding toggles to an old acknowledgement. Connect the common engine's admission enable to `run_enable || admission_busy_o`. The source ledger's ordinary settlement and abort settlement are separate registered single-bit crossings. Abort settlement registers `fault && source_settled` before synchronization, preventing a stale healthy-empty observation or a combinational decode glitch from authorizing recovery. A fatal transport reset must not reset this observation path: the source consumes every outstanding W and produces the complete required R/B sequence under its surviving AXI reset, while the common engine can discard its aborted copies. A consumed OKAY B remains covered by its exposed ledger until retirement, including a fault while its real handshake feedback is still crossing. Healthy rearm also waits for actual retirement of every local ledger entry before replacing epochs or resetting generations; acknowledged-only settlement is sufficient only after faulted transport abortion. The bridge accepts rearm only after the fresh disable handshake has completed. The fixture delays the real retirement FIFO consumer, requests a fresh healthy boot, and checks that the old configuration and identity remain until consumption, then proves fresh traffic. An immediate rearm pulse at enable fall must be ignored. Wrong-generation retirement records are injected through the actual FIFO writer while a same-slot write/read owner is live; neither their error code nor malformed feedback flags may modify that owner. The retirement observer changes state only on the actual VALID/READY handshake.

The bridge implements logical 64-byte bucket leases with whole-source revocation. Every granted mask is reserved before publication. A source accepts a lease hit directly only with a free local ledger/response slot and acceptance-FIFO capacity. A miss publishes one complete request; the coordinator rotates fairly between sources. Conflicting rights remain reserved until the former source has frozen all address acceptance, handshaken and retired every accepted transaction, and acknowledged the exact command with a stable next-acceptance sequence. The coordinator also waits for that sequence to import. Descriptor import, W, response, feedback and retirement transport continue throughout this drain. Each command and acknowledgement carries boot/configuration epochs and a monotonic token; reset recovery invalidates old rights. Invalid or unmapped requests use all buckets. Ownership and stalled control-payload stability have RTL assertions.

The source footprint covers the entire conservative burst interval, including the full WRAP interval. A valid burst lies inside one page, and admitted regions have page-aligned boundaries, so complete region containment checks all eight regions without per-beat prevalidation. The admitted map is injective and preserves the low six address bits: disjoint logical buckets therefore prove disjoint memory granules even under arbitrary allowed permutations. Different pages can collide in the same bucket and take the normal revoke/drain path. The channel scheduler still owns bank timing. The healthy R register can replace a consumed beat at the same edge when event storage permits; transaction-boundary exposure and final-handshake records retain their own identity.

The saturated transport measurement uses independent continuously offered AW and W streams on both ports, consecutive W beats, multiple outstanding transactions and always-ready B/R. Reads use independent continuously offered AR streams. Each steady-state window counts completed payload bytes after 128 transaction completions and before drain, over 832 further transactions from an unchanged address stream. A separate startup-and-drain measurement includes the complete 1,024-transaction run and trailing accounting drain; neither interval is presented as the other. Logs report source VALID/READY duty, coordinator idle/grant-send/grant-acknowledgement cycles, acknowledgement waiting versus import backpressure, source grant-waiting cycles, FIFO-full stalls and peak local ledger occupancy. Earlier serialized-driver measurements remain historical development evidence. This fixture measures the host transport against an independent response consumer; it does not establish memory-controller bandwidth, DFI behavior or the final 12.8 GB/s requirement. The assembled host and combined controller need their own behavior and throughput evidence.

## Assembled host behavior

The [assembly runner](../../dv/host/assembly_run.py) connects the real AXI bridge and common host core to an independent byte-memory responder. It uses host/AXI periods of 1.25/2.5/3.5 ns with a 0.375-ns phase offset and exercises a 128-beat burst whose 32 granules exceed queue depth 16. Other checks cover an accepted AW before delayed W, overlapping reads on the other port, a clean queued OKAY aborted before its stopped source can expose it, stable exposed B and late error, peer reset and core reset with remaining W obligations, and successful traffic after fresh-boot recovery. An additional consumed-OKAY fault case stops the host clock so exposure/handshake feedback cannot reach the core before the fault; the surviving source ledger must report the late error.

Reports retain source hashes, exact commands, clock periods, logs and source-change detection. Split C++ generation and explicit make optimization settings bound simulator compilation cost without changing RTL assertions. The recovery cases use the actual per-domain transport reset-ready outputs, then require settlement to remain stable for eight CK samples. The fixture samples at a later clock edge after changing enable so a same-delta old combinational value cannot falsely satisfy that assertion.

## Independent lease admission checks

The [lease runner](../../dv/host/lease_run.py) captures the real host source-list closure before compilation and rejects later source drift. Its independent byte oracle records actual source AW/AR/W/R/B handshakes and integer-picosecond acceptance times. It checks complete per-port imports, forbids crossing an older unimported overlap, and replays completed transactions in sampled source order at settled barriers. Memory effects occur only at the responder's physical completion witness. The fixture requires a decisive disjoint source/import reversal; direct inspection of a lease mask is not its ordering oracle.

Eighteen directed families cover complete INCR/WRAP/FIXED footprints, partial/unaligned and malformed writes, invalid all-bucket requests, accepted-but-unimported AW with delayed W, revoke-head READY cutoff, stopped owner clocks, actual response backpressure, fatal settlement, stale boot rejection, accepted-descriptor disable drain, stale command epochs and stale acknowledgement tokens. The runner additionally requires deliberate read-data and physical-memory corruptions to fail with their specific independent byte-oracle diagnostics. Expected corruption failures are retained separately from successful behavior commands.

The assembled-host measurement uses two AXI128 sources at 400 MHz, a 375-ps port-one offset, host800 and depth16. AW/W are continuously offered independently with multiple outstanding IDs and always-ready B. Each burst is 64 bytes and both streams use seven legal pages in a 64-KiB region. The disjoint case sends 24 writes per port, discards the first 12 combined B handshakes, measures the next 24 and leaves 12 for drain. Development evidence records 1,536 bytes over 120 ns, or 12.8 GB/s. The collision case sends 32 writes per port to legal addresses separated by 4 KiB that share the same ownership bucket; it discards 16 combined completions, measures 32 and leaves 16 for drain. That separate development measurement records 2,048 bytes over 820 ns, or 2.497561 GB/s. It exposes conservative whole-source handover cost without constraining accepted addresses.

Each window begins at the warm-up B handshake and ends at the specified later completed B handshake. Logs retain per-port AW/W VALID, READY, handshake and stall counts within the window. A behavioral channel witness uses zero added service delay during these two streams; an independent byte-memory oracle checks effects and responses. These bounded host measurements do not establish physical-bank/ECC ownership, channel timing, mixed-traffic service or combined-controller throughput. The larger transport fixture above separately measures reads and writes and reports steady versus startup/drain intervals.
