# Channel implementation

`lpddr5_mc_channel` implements the CK-domain composition against the accepted foundation at `8fefc83619f66eb89a6522727adeed797a4cc4c2`. The contribution supplies channel RTL and focused owning tests; host/CDC integration and final combined qualification remain downstream. The [explicit source list](../../rtl/channel/files.f) and [owning check flow](../verification/channel.md) describe reproduction. Authoritative requirements remain [interfaces](../spec/interfaces.md), [integrity](../spec/host-ecc.md), [control](../spec/control.md), [profiles](../spec/profiles.md) and [performance](../spec/performance.md).

## Ownership and interfaces

The channel composes atomic configuration, lifecycle, inline integrity, the physical backend, maintenance, updates and FSP. `lpddr5_mc_backend` composes logical-to-physical tracking, scheduling, data, WCK, rank-local write epochs and exclusive MRR/ZQ transport. The host owns request/completion/configuration CDC, AXI response storage and actual host settlement. No asynchronous crossing is introduced inside this CK-domain hierarchy.

Requests carry the canonical granule plus explicit boot/configuration epochs. Stale epochs are consumed without memory effects. The channel retains the original granule identity through completion transfer for correlated first-error reporting. Its internal completion adds corrected/uncorrectable/syndrome fields; the host adapter must project the shared fields by name rather than use a packed cast. Integrity summaries travel through notifications independently of the host completion subset. Logical completion moves the remaining response obligation into reserved host storage; it never substitutes for B/R exposure or handshake. Both strict and posted configurations currently use conservative final-integrity logical completion. The standalone epoch owner separately supports early posted notices and later integrity updates; the composed channel does not expose those early notices.

`host_settled_i` and `reset_confirmed_i` are external host/reset attestations. Physical pin, page, WCK and integrity drain are computed internally. PHY-master integration additionally supplies `rank_report_valid_i`, `rank_self_refresh_i` and `phy_refresh_done_i`. Report validity must fall and reassert with the actual per-rank state at each master return; only actual PHY refresh execution discharges refresh obligations. Reconciliation must connect these attestations to their real owners.

## Supported profiles and addressing

The typed profile validator admits the existing complete numeric fixture set, one/two ranks, WCK ratio two/four and service divisors one/two/four. Link ECC requires ratio four, discovered device support and raw parity transport. Read-link plus read-DBI, nonzero data-CS gaps, incomplete MR images and unqualified timing changes reject admission. `fixture_profile` mirrors the qualified numeric table; independent tests load their own profile assignments from canonical JSON. These restrictions do not establish vendor PHY interoperability.

Granule `column` is a six-bit index in units of 32 bytes: upper six bits are zero and BL32 requires bit zero clear. An inline 32-byte operation selects its half using column bit zero. Invalid row/column, wrong-channel and unpopulated-rank requests return failed completions without a memory command. The standalone scheduler consumes already validated physical requests; its ready signal does not itself produce host error responses.

## Physical transfer and scheduling

A data slot retains every word and both byte slices through physical completion. Read assignment follows each slice's next expected enable time, permitting BL32 words from different commands to interleave through split gaps. DNV consumes the word and returns failure. Early, missing, wrong-rotation and unsolicited return events latch a data fault. Write completion waits for the final DRAM pin edge and conservative path flushing including `twrdata_delay`. Read completion requires every word/slice and the final pin edge. Completion payloads remain stable under backpressure.

The scheduler owns separate finite direction queues, live page/timing checks, DQ reservations, age/QoS arbitration and byte caps. Selection divisors affect new picks only. Accepted ACT and synchronization/access pairs finish on the following CK; timing, age and mandatory maintenance advance every CK. Strict caps charge actual issued bytes; zero disables a direction. Work-conserving borrowing requires no eligible opposite traffic. Host ordering before dispatch remains the host owner's responsibility; queue overlap checks do not replace dependencies on already issued operations.

Full-rank closure uses PREab after every open bank's precharge deadline and global tPPD permit it. Recovery uses tRPab while retaining a later tRC fence. Pair refresh closes only its affected banks. Maintenance and maximum-row closure are gated by actual CA ownership. WS_OFF occupies an empty CA cycle and cannot displace an accepted pair. The physical backend reserves data and epoch capacity before starting an access pair.

## Integrity

`lpddr5_mc_ecc_pkg` implements SECDED64+8 and raw data/DMI link codecs. The logical adapter assigns monotonic internal tags, splits masked BL32 into distinct MWR16 operations and aggregates final outcomes while retaining the full caller identity. Backend slots can be recycled only after their remaining obligations transfer into another reserved owner.

Write-link membership retains up to sixteen physical writes per rank. Drain starts with a profile-derived allowance for data recovery, PREab, WCK disable and serialized MRR service. The shared MR43 transport selects the oldest ready epoch first. Polling waits for physical completion, closed/recovered pages and disabled WCK; it does not wait for the logical completions that depend on MR43. Final logical write completion follows the actual returned MR43 result and read/clear recovery. Standalone posted handling retains response exposure history, full epoch/generation identity and late-error diagnostics.

Inline integrity serializes one protected data/check-line transaction. Partial writes read the check line and old data, correct and merge enabled bytes, then write data and the merged check line under the same lock. Corrected reads scrub under that lock before a newer operation can pass, so no deferred scrub version queue is needed. A failed data/check write records per-word poison in a bounded CAM; a successful full protected-word rewrite clears the matching poison. Exhausting poison capacity faults closed. This implementation trades inline concurrency for a simple ordering boundary and has no inline throughput promise.

## Diagnostic notifications

`lpddr5_mc_notifications` stores independent occurrences from lifecycle/configuration, logical integrity completion and fault detection. `notification_valid_o/notification_ready_i` transfers one immutable record into the host's reserved mailbox storage. Its events, optional canonical error and boot/configuration epochs remain stable while stalled. Multiple same-bit occurrences remain separate. Ordinary `status_o.events` is zero; the adapter must send ordinary snapshots with `error_valid=0`. APB consumes canonical CE bit 5 and UE bit 6 once per notification, and owns software W1C and its first-error record.

Internal channel completions retain corrected/uncorrectable/syndrome summaries through data, masked-half aggregation and inline scrub. A logical integrity result creates one notification on transfer to host storage; earlier inline decoder pulses do not create duplicate counts. Rejected malformed ingress fails its response without inventing an ECC occurrence. Each queued error contains its own detail independently of the retained first-error snapshot.

The FIFO defaults to sixteen entries and can accept three sources per CK. Overflow blocks trust/service, preserves existing entries and retains a separate overflow report until queue space becomes available. Confirmed destructive recovery clears the volatile overflow fault, but leaves queued notifications and their original epochs intact. A queued pre-recovery occurrence must reach software with its original boot/configuration metadata after recovery, without replacing the live BOOT_EPOCH/configuration status. Reconciliation must distinguish occurrence admission from live-snapshot freshness: a current-boot status filter must not consume and discard an older retained occurrence. Relabeling it with the current boot would lose its provenance. The host/APB binding of that distinction remains unverified here.

The optional CK diagnostic seam requires `first_error_clear_i` with the exact `first_error_clear_version_i`; outputs expose validity, monotonic version and occurrence epochs alongside `status_o.first_error`. A simultaneous new error wins over clear, and an old version cannot erase a newer error. Version exhaustion faults closed. This seam cannot clear fault/trust/maintenance or queued notifications. APB currently has no CK diagnostic-clear command; tie this input inactive unless a coherent versioned binding is implemented. Its local software W1C needs no CK clear path.

## Configuration and management

`config_crc` uses reflected CRC32, polynomial `0xedb88320`, initial all ones, packed bits from least significant to most significant, then complement. Prepare freezes one immutable image; common commit checks that image and exact sequence again. Repeated publication of the active image is idempotent. Abort or invalid commit disables the consumer. A normal FSP decline discards only prepared state, preserves the active point and consumes the attempted sequence. Destructive recovery never lowers the retired sequence fence.

A profile change cannot commit until the actual FSP engine asserts `fsp_ready_o` for the prepared epoch. After full prepare, the host adapter issues `CH_CMD_FSP` from frozen target metadata and withholds its accepted PREPARE acknowledgement until readiness. `target_fsp_i[1:0]` selects bank zero/one/two; `target_frequency_i[4:0]` is zero for ratio two and one for ratio four. The engine freezes them at admission. `fsp_declined_o` is a one-CK indication; an adapter must latch it and wait for prepared state to clear before returning a terminal normal-decline acknowledgement. All destinations must become ready before common publication. Initial and scheduler-only commits still require host settlement and real drain.

The FSP engine requires fresh low-before-minimum PHY acceptance, writes FSP-WR, seventeen target MRs and FSP-OP, waits the long guard and six running CK, releases its registered request, then requires a later completion high. The update engine enforces sampled acknowledgement and registered-release bounds. PHY acknowledgement additionally requires the explicit lifecycle update window, even when RUN or boot happens to have empty pins. Ignored opportunities decline normally; late, stuck, reasserted or unsolicited acknowledgements fault. Lifecycle remains in DRAIN with maintenance enabled until the corresponding operation has sufficient refresh reserve to start.

Maintenance is the sole RAA/retention owner. `PER_BANK_REFRESH` is a fixed elaboration policy, default zero/all-bank; there is no mutable live refresh-mode sideband. It preserves paired counters across normal self-refresh, orders all eight REFpb pairs and discharges periodic retention only for a complete round. RFM does not advance the periodic timestamp. Actual self-refresh membership suspends external deadlines; SRX creates a separate extra-refresh-before-reentry obligation. MR4 and background ZQ visit every populated rank. Polling starts early enough to reserve traffic/precharge/refresh drain, serialized rank MRR service and arbitration slack, with a minimum 600-CK lead before the unchanged 3000-CK MR4 watchdog. REFpb needs the larger profile-derived lead; waiting until 2400 CK can leave insufficient time for a complete pair round and recovery. The hottest rank's MR4 code applies globally. Tighter thermal intervals expose debt and block ACT admission; the bounded emergency-drain policy stops further traffic while servicing the debt. Repeated reports cannot extend its deadline. The maintenance owner distinguishes closed rows from completed REF recovery, so a recovery interval does not trigger a second full traffic-drain reserve. Register/lifecycle handover still requires completed recovery. With REFpb enabled, rank rounds interleave by the last actual pair issue while retaining each rank's prescribed pair sequence. When the complete `maintenance_admission_budget(profile, per_bank=1) + register_service_budget(profile) + 8 CK` cannot fit the current thermal interval, maintenance falls back to all-bank REF and the backend uses that same policy for admission reserves. A minimal pair-round duration alone is insufficient: at thermal code 13 it can fit while the remaining drain/register allowance cannot. This replaces any partial pair round with a full all-bank discharge; no partial round alone counts as retention service. MR4/ZQ admission then reserves one rank transaction, allowing REF between ranks; the earlier uninterrupted two-rank reserve starved MR4 at the shortest thermal interval. The connected stress fixture checks this arbitration with mandatory RFM and thermal transitions; its execution status is recorded with the owning evidence.

Lifecycle requires fresh initialization, training token/profile epoch, known rank state and disabled WCK before trust and service. Low-power decline/wakeup, update-before-SRX, PHY-master return and destructive recovery have explicit states. Recovery requires host settlement plus confirmed destructive reset, increments the boot epoch, invalidates old training/configuration, clears volatile maintenance/integrity tracking and retains first-fault diagnostics. A timer or interrupt clear cannot restore trust.

## Verification and integration obligations

The [owning checks](../verification/channel.md) cover actual component RTL and a connected channel with a CA-driven memory fixture. They check both ratios, CK/CK2/CK4, masked and split transfers, link/inline integrity, normal/always-on WCK, malformed ingress, maintenance and management/recovery. Development failures and corrections remain retained with the result; only reports for the final unchanged source establish its passing checks.

Reconciliation must connect the host's atomic publication, reserved response storage, response exposure/handshake feedback, real CDC/reset paths, actual host settlement and destructive reset confirmation. It must also deliver retained old-boot notifications without corrupting current status, project completion fields by name, and bind PHY-master state/refresh attestations to their actual owners. The channel's conservative final-integrity completion leaves the host responsible for stable exposed responses and complete fault settlement. The optional CK diagnostic-clear seam remains inactive until a coherent versioned command path exists.

Qualification must run the independent combined environment, broad supported width/queue/channel matrix, fault sensitivity and coverage closure. It must establish actual throughput and conditional fairness against the unchanged [performance criterion](../spec/performance.md), including measured issue gaps and suspended intervals. The bounded owning fixture does not prove those final checks. No synthesis, physical timing, PPA or vendor qualification is claimed. Portable implementation risks include the wide combinational selector, time comparisons, ECC fanout, packed-storage reset cost and CK800 timing closure.
