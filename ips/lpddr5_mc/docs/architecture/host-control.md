# Host and control implementation

This page describes the host/control contribution. The canonical [interfaces](../spec/interfaces.md), [host and integrity behavior](../spec/host-ecc.md) and [lifecycle](../spec/control.md) remain authoritative. The [programming guide](../programming/host-control.md) describes APB use; [owning verification](../verification/host-control.md) records reproduction and evidence limits. Combined channel wiring, PHY qualification and final throughput qualification belong to the integrated controller.

## Owners and clocks

`lpddr5_mc_apb` owns staging registers and all-channel publication in `pclk`. `lpddr5_mc_control_link` carries immutable configuration, exact acknowledgements and coherent status through bundled mailboxes to each channel. A channel validates its actual numeric profile and computes real pin, ECC, maintenance and lifecycle drain. A successful queue transfer cannot substitute for those witnesses. The full committed host image and its epoch must reach the host before admission reopens.

`lpddr5_mc_host_register_decode` extracts regions, all sixteen QoS classes, per-port read/write limits, granule/ECC/posted modes and boot/configuration epochs from that coherent image. It neither validates a PHY nor authorizes traffic. `lpddr5_mc_host_core` owns burst validation, write buffering, transaction hazards, granule routing, read assembly and retained response storage in a common host clock domain. `lpddr5_mc_host_channel_link` crosses granules and their epochs to a channel and crosses physical/integrity results back; response exposure/handshake records travel separately.

`lpddr5_mc_axi_bridge` and its per-port endpoints own independent AXI clocks. A local ledger reserves an ID, beat count, slot/generation and complete response capacity before source acceptance. Its lifetime includes actual AXI handshakes and the host core's retirement acknowledgement. W data follows AW order, including malformed WLAST; an early WLAST never truncates the admitted count.

## Admission order and hazards

The global conflict order must be established before source READY, rather than reconstructed from asynchronous FIFO arrival. The initial bridge uses one acknowledged common address grant. The source retains its offered address while the grant crosses, accepts it only when READY and VALID meet, and returns that exact accepted packet. The bridge waits for its import before releasing the reservation. Per-port sequence numbers cover AW and AR together, with AW before AR at a tie. The core consumes each sequence exactly and preserves port-zero priority for common-domain ties.

An accepted AW immediately reserves its full byte-range hazard before any W arrives. Every write is completely buffered and validated before a granule can have a memory effect. Older unfinished overlaps block younger accesses; nonoverlapping transactions may execute in parallel after their order is known. The core uses stronger per-port response ordering than AXI requires: each direction returns transactions in admission order, which preserves every same-ID ordering requirement.

Aligned full-width INCR beats are coalesced into the configured 32/64-byte granule. Other admitted burst forms use their exact beat byte ranges and lane strobes. Region offsets use an invertible permutation, regions pack in ascending base order, bit six stripes two channels, and rank capacity accounts for inline ECC reservation. Invalid forms, holes, address-width/4KB crossings and unmapped bytes settle with DECERR and no effects. Malformed decoded W strobes/WLAST settle with SLVERR after the complete admitted W count. AxLOCK has ordinary effects and never produces EXOKAY.

## Completion, exposure and storage

Queue acceptance, physical completion, integrity settlement, transport transfer, AXI exposure and the actual handshake are separate events. Every completion retains tag, generation, boot epoch and configuration epoch. The core rejects mismatched/stale identities without changing transaction or credit state. A read result is assembled only after its channel reports complete physical and integrity results; the channel owns individual word/slice/split identity before that boundary.

For asynchronous response queues, `POSTED_EARLY=0` is the conservative implementation policy: the core waits for integrity as well as physical completion before placing an OKAY into the return transport, even when posted mode is selected. The accepted contract permits this added latency. Optional common-domain early eligibility requires an endpoint that arbitrates actual exposure and errors in that same domain; enabling it for an ordinary asynchronous FIFO would be unsafe.

The actual source endpoint owns BVALID exposure and BVALID/BREADY handshake records. A global abort must fence a still-unoffered return before it can become OKAY at the source. An already exposed response remains stable through backpressure; applicable later failures raise late-error evidence. Delayed feedback must not erase that evidence. The integration must connect the real global-fault assertion path; waiting for integrity does not eliminate a later ownership-loss race.

Completed channel data/error ownership can transfer into reserved host response RAM before the final host handshake. Unresolved posted MR43 epochs retain their full identities and exposure history independently of recyclable command/data slots, including both ranks concurrently. A second posted integrity update never creates another B. The host RAM and transaction dependency remain reserved to final handshake and retirement. This separation lets long AXI bursts progress beyond the finite channel queue depth.

## Reset, fault settlement and recovery

The CDC transports use asynchronous assertion, separately synchronized release, Gray-pointer FIFO controls and stable bundled mailboxes. Either endpoint reset flushes transport entries and latches a fence at both ends. Releasing reset never re-enables a link; both owners must explicitly rearm it after settlement and fresh epochs. Each owner waits for the actual transport reset-ready output in its own clock domain before issuing that pulse. A separate replica synchronizer or an assumed delay cannot prove that the transport accepted rearm. See the [constraint guidance](../../constraints/host/README.md).

A surviving AXI ledger remains outside remote/core reset. On a fault it stops new AW/AR, consumes outstanding W in order and returns every remaining R beat and one B per accepted write. Existing DECERR stays DECERR. Already exposed B/R values stay stable; later unoffered beats use the defined error path. Only an explicitly coordinated reset of that actual AXI interface may discard its ledger. Empty queues, an IRQ clear and elapsed time cannot prove settlement or retention.

The assembled host selects `EXTERNAL_ABORT_LEDGER=1`: after an abort, the common-domain core discards its transaction copies instead of waiting for feedback through the flushed transport. The surviving source ledgers own all remaining bus responses. Their combined fault-and-settlement witness is registered in the source domain before synchronization, so an earlier healthy-empty observation cannot authorize recovery. Quiesce also waits for an exact disable-generation acknowledgement from every source; each source must observe both synchronized enable stages clear and withdraw or finish its candidate before acknowledging. A stopped source clock cannot silently count as quiesced.

Recovery requires complete host settlement, the channel's confirmed destructive reset, invalidated old tracking and fresh boot/training/profile epochs. Configuration sequence, source sequence, generation and tag exhaustion require a coordinated drained epoch transition; silent wrap is unsupported. No counter or synchronizer alone proves ownership recovery.

## Portable implementation costs and current limits

The core reserves `2 * PORTS * DEPTH` transaction entries and 256 maximum-width beat records per entry. At two ports and depth 64, the unpruned 256-bit payload RAM is 2 MiB, with another 256 KiB for 32-bit strobes. Smaller bus widths can permit pruning; no synthesis result establishes that saving. Metadata, CDC FIFOs and response ledgers add storage. Large combinational hazard scans, mapping permutations and indexed multiport RAM access are timing/area risks requiring integration and synthesis assessment. No technology-specific PPA or clock closure is claimed.

The serial acknowledged-grant development path measures 3.657143 GB/s in each direction with saturated AXI128/400 sources and a host800 clock: 28,160 completed bytes in 7,700 ns, excluding warm-up and drain. The fixture records 4,840 of 6,160 CK waiting for source acknowledgement, no import or FIFO-full stall and peak ledger occupancy three. This isolates the per-address roundtrip as an admission constraint; it does not establish the final controller rate. Disjoint authorization with acknowledged revocation is under development and has no passing implementation claim yet. The accepted target remains unchanged. Final bandwidth evidence requires the real combined channel and the agreed measurement window.
