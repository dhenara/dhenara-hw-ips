# Independent system verification environment

This environment qualifies independent observation models, adapters, bus agents and their sensitivity fixtures. The source contains the [accepted reference foundation](../spec/contracts.md), host/channel RTL and developing controller bindings. A passing environment report sets `controller_qualified: false`. Actual combined controller correctness, CDC/reset behavior, coverage closure and throughput require later execution against that controller.

The [current qualification matrix](qualification.md) records combined-controller evidence and remaining release checks. The [coverage map](../../dv/system/coverage.json) identifies executable environment and foundation tests; its historical combined pending labels are reconciled by that matrix and do not mean all those behaviors remain untested. The runner validates every cited test identity and the result of each environment test. A foundation reference is not an extra controller pass. The full runner executes the existing foundation flow unchanged and records its separate result.

## Actual RTL binding

The [integration runner](../../dv/integration/check.py) compiles the aggregate [RTL list](../../rtl/files.f), retains exact source hashes, literal commands and logs, and checks a behavior completion marker for each simulation. Give each observed run a fresh report directory: different JSON filenames in one directory still share raw observation filenames. The runner exclusively reserves its trace paths before compilation and refuses existing files or another concurrent writer. Its tooling regression checks trace preservation and distinct/concurrent output ownership before simulation. A refused directory must be replaced with a new one; do not delete earlier evidence to reuse it. Long-running checks need a deadline that includes compilation and every selected scenario; a process timeout is a failed/incomplete execution even if earlier scenarios passed.

The [combined runner](../../tools/check_controller.py) accepts repeated `--step` names for focused recovery of interrupted checks. It retains the exact selected names and `full_suite_selected`; a passing partial selection establishes only those steps. Earlier passed results require their own unchanged-source and evidence bindings. The APB publication family runs four full scenarios and has a 3600-second step deadline; other connected steps have 1800 seconds. These finite deadlines cover build and simulation and do not replace behavior checks.

The [raw observer](../../dv/integration/lpddr5_mc_observer.sv) records actual AW/AR/W and offered/handshaken B/R at each source clock, and CA/WCK/data/enables/returns at CK. Picosecond timestamps preserve fractional CK/source edges. The [connected checker](../../dv/integration/connected.py) feeds these observations to independent host, literal command, physical-memory and returned-slice models. It derives completion from actual decoded command/data effects; DUT completion flags are not an input. Its present supported binding is clean, identity-mapped, non-ECC/non-DBI traffic. The connected [WCK observer](../../dv/integration/wck_observations.py) additionally checks each serialized half-WCK edge indication on both byte slices against actual decoded CAS/access commands and the qualified physical path delays. It checks enable, static/half/full-rate preamble, continuous same-rank/direction reuse, expiry, postamble, WS_OFF and full disable before a new synchronization. Ratio-two upper phases must remain inactive. Each channel reports epochs, accesses, sampled half-WCK positions, disabled epochs and whether WCK was still active at the trace end. A finite trace may end after its full physical postamble with WCK active; that is explicitly reported and does not demonstrate disable. These digital output controls do not establish electrical WCK behavior. Pin behavior through destructive reset and ECC management traces remains separate.

The [sensitivity check](../../dv/integration/check_observations.py) requires a passing original trace, then rejects fifteen active mutations covering physical/returned/AXI data, rank selection, enables/continuous CS, CK timestamp, response identity, premature success, a missing trace tail and five WCK edge/enable/rank/CS violations. The mutation accounts for write-data delay and active lane/mask selection.

For plain datapath traffic, `--axi-stress-seed` selects 64 sequential seeded writes followed by reads from the opposite port (the same port in a one-port configuration). It varies FIXED/INCR/WRAP bursts, 2/4/8/16 beats, every supported beat width, legal unaligned starts and sparse byte strobes. Each write delays W after accepted AW and holds an actually offered B; each read holds an actually offered R. Four cases each inject an out-of-range strobe, early WLAST, missing WLAST and a 4-KiB-crossing descriptor. Every admitted W/read count must settle, rejected writes must leave memory unchanged, and all source responses must remain stable under backpressure. The [stress accounting](../../dv/integration/axi_stress.py) reconstructs descriptors, W validation errors, response classes and stalls from actual observations and requires 64 AW, 68 AR, 48 OKAY/12 SLVERR/4 DECERR B and 64 OKAY/4 DECERR read transactions. It also checks the exact seed/completion marker. The connected replay independently checks source data and physical effects. Its physical read binding follows the documented full-width aligned INCR coalescing rule and otherwise requires one complete granule per source beat, including separate repeated FIXED returns. Padding outside narrow AXI ranges must arrive too; duplicate slices, extra physical reads and incomplete padding fail. Repeated physical write bytes must match every validated FIXED W value in order; missing or excess effects fail. This bounded workload does not cover concurrent overlap, forwarding, merging or queue exhaustion. Reports establish which seeds/configurations passed; the option itself is not coverage closure.

The notification family covers first-error/count/IRQ and explicit performance-capture retention through fractional operational resets, queued and delivered events, and an in-flight event while the APB clock is stopped. Its status transport remains in the cold-reset domain; configuration/acknowledgement transports reset operationally. The test checks exactly one delivery after the APB clock returns.

`--family datapath --axi-overlap` selects a directed two-port workload on independent source clocks. Four turns alternate the originating port and channel stripe. Each admits an AW, two same-ID overlapping reads and a younger same-ID write before supplying W. The first two reads must retain the first write's snapshot after the younger write is buffered; the competing port holds AR while the original responses remain backpressured, then reads the final bytes after ownership turnover. The bridge deliberately excludes conflicting cross-port admission until the original source's transactions retire; this test checks that policy instead of assuming both ports can accept overlapping addresses concurrently. It also fills every read/write response slot on each port, holds an actually offered response, requires 32 blocked source cycles at full capacity, then frees credits and settles the additional request. Sampled cycle flags independently establish the live depth, blocked admissions and offered B/R stalls. The completion marker and assertions cover the directed sequence; only an executed report establishes a pass.

The [physical ownership binding](../../dv/integration/physical_ownership.py) retires independently observed pin/return work before source B/R handshakes, so a held response cannot conceal younger overlap errors. It requires complete validated W before a write command, distinct per-transaction physical granules, all enabled bytes and the full pin tail. Reads capture their serial snapshot after every required return, including padding, before a younger overlapping write changes memory. Duplicate commands, missing effects, premature physical retirement and older unfinished overlaps fail. Ambiguous disjoint narrow requests sharing one overfetched granule need another correlation witness and are rejected by this binding. These checks exercise serial-equivalent execution; they do not demonstrate an implemented forwarding/merging optimization or ECC dependency behavior.

## Combined check command

The controller regression polls dedicated TRAIN_DONE before ENABLE and reads actual per-channel device capabilities through APB, including nonzero paired-bank MR57. Its normal recovery scenario observes two changing MR4 values per channel through the real memory/channel/status/CDC/APB path, then checks that destructive recovery clears old observations and a fresh boot publishes its new capability descriptor and fresh temperature. The notification regression additionally rejects wrong-boot and wrong-configuration snapshots while retaining error detail. The [C example behavior test](../../dv/integration/control_example_test.c) compiles the delivered helper itself and covers cold/quiesced publication, running/fault rejection, changed boot, valid/epoch prerequisites, one-command bounded timeout and invalid callbacks. This callback fixture complements real APB admission checks; it does not replace them.

## Timing origins and continuous streams

The correction tests retain the review's four false-pass sequences and check each boundary one CK early and at the legal edge. `DramModel` uses pin CK after the explicit command path delay; it retains rank state and independent command history, so traffic to another bank cannot erase a recovery interval. ACT timing starts at ACT-1; pair completeness is checked at the required adjacent ACT-2. The previous BL16 same-bank regression now tests an actual illegal three-CK gap rather than rejecting the legal four-CK boundary.

| REFpb/RFMpb | Actual maintenance command: tpbR2pbR before another pair; tpbR2act to another bank; target recovery tRFCpb/tRFMpb and ACT-to-maintenance tRRD. Sections 7.5.1/7.7.6, Tables 237/238 and refresh-management separation tables. |
| Read/write turnaround | Actual prior CA, RL/WL and BL/n effective span; tWTR starts after WL plus the complete effective burst, including split BL32. tRTW follows Tables 347–349 for admitted ODT-off profiles, including write-link input use. Pin collisions and rank overlap are checked independently. |
| MR timing | MRW-2 is the model's conservative completion origin; wait tMRW to another MRW and tMRD to other commands. MRR period and data/MR transitions follow Tables 252/372. This adjacent-pair policy can be stricter than the standard's MRW-1 period origin by one CK. |
| Self-refresh | Only idle/recovered banks enter; explicit state rejects ACT/data/maintenance during self-refresh. SRX uses tXSR for bank commands; allowed MR/CAS/MPC operations may occur during recovery under Table 243. Minimum residence is 15 ns rounded up at the selected CK. |

## Source order and response ownership

Observe AW/AR only at actual source AXI `VALID && READY` edges. Assign a testbench correlation key there, and preserve chronological order across independent clocks. At an exact common sample instant, port zero precedes one and AW precedes AR per port. CDC FIFO insertion/import is not that order. The trace adapter buffers one bounded sampled instant and sorts its admissions by these ties; it never uses crossing arrival to reorder source times. A full AW range exists before its first W. Observe each port's W handshakes in AW order.

The source-order sensitivity test rejects an overlapping read overtaking an earlier write. The grant monitor tests revocation racing source acceptance, credit exhaustion, disjoint concurrent reservations and stale reset epochs. These are synthetic monitor tests; actual phase/skew/reset variation and a deliberately faulty CDC implementation remain pending. A centralized or partitioned admission implementation is free to optimize disjoint traffic while preserving the observable order and the unchanged benchmark.

`HostScoreboard.forwarded` overlays every older fully buffered overlapping write in source order, byte by byte. Successful retirement waits for all contributing physical and integrity outcomes, including overwritten contributors; any failed dependency prevents success. The generic host trace currently expects individual physical write witnesses. [MergeMonitor](../../dv/system/merge.py) validates identical decoded region/channel/rank/ECC/profile/boot/config context, one physical granule, complete original W validation, absence of intervening overlapping reads, final byte composition and every original response dependency. Register each original context before `begin`, observe merged bytes with `pin`, and call `physical` only after all enabled bytes. `begin` exclusively reserves every original until physical completion, rejecting duplicate or overlapping groups even when all resulting bytes would match. It rejects originals with earlier partial/complete physical effects and rechecks their ownership before pin effects and completion. Integrity and B exposure/handshakes remain individual. Disjoint pending merges and new writes after retired originals are supported.

Physical correlation IDs are unique within a host epoch; adapters must include slot generation in that integer ID rather than reusing a live correlation. Duplicate completion, stale epochs and all physical effects during a fault fail. Only after the host has settled and `HostScoreboard.reset(destructive=True)` succeeds may `MergeMonitor.reset()` clear its reservations/history and permit correlation ID reuse in the new epoch. Reusing a hardware slot within an epoch requires a new correlation ID. These APIs are qualified on fixtures; the existing JSONL host adapter retains its individual-write format. Reconciliation must bind actual merge observations to this API.

Physical completion, integrity outcome, transfer into reserved host storage, source BVALID exposure and source B handshake are different events. `LifetimeMonitor.transfer` can free a channel slot only after a reserved owner inherits the obligation. It does not expose a response. MR43 membership/history survives posted response handshake and slot reuse, independently for every rank. Live adapters call `poll(rank, ck)` at the actual MR43 command, then `result(rank, ck, failed, read_clear_ck=...)` at the returned result with a qualified read-clear completion. The result cannot precede tMRR; reopening cannot precede tMRR+tMRW from the sampled poll. Defaults are the admitted eight/twelve CK, and adapters must pass the active timing profile. New rank-local writes are blocked from poll through that guard; unrelated ranks remain eligible. Every timestamped API (`allocate`, `poll`, `result`, `advance`, and the `mr43` convenience helper) validates a nonnegative integer CK against one shared observed time across ranks. Earlier timestamps, including a poll before its first write or a result before already observed time, fail before settlement. Equal-edge events and rank-independent epochs remain legal. Every time-bearing event checks the outstanding 256-CK poll deadline, so omitting `advance` cannot hide a missed poll. `read_clear_ck` is a future reopening guard, not an observation that advances the shared clock. Destructive reset clears volatile rank guards but preserves absolute simulation time; it never permits clock rewind. Untimed APIs operate at the last observed CK, so live adapters must advance to their actual sample before invoking them. The old `mr43` helper advances through both poll and result and must not be used as a live pin observation. Interleaved rank events must be supplied chronologically using the separate APIs. Failure before exposure changes the unoffered response to SLVERR; after exposure the response remains stable and the applicable late error is recorded. Failed operations may transfer an error before pin completion so fatal settlement can finish; destructive recovery still requires host settlement and explicit reset confirmation.

Posted OKAY may wait for integrity, including conservative asynchronous `POSTED_EARLY=0`; there is no required early-B latency. Only actual source BVALID marks exposure. A clean integrity result does not make an internally queued OKAY immune to a later global fatal/ownership fault. The environment tests that race before/after transfer and exposure, prolonged stalls, reset and stale identity feedback. A deliberately unoffered OKAY after fault is rejected. Actual same-edge arbitration and delayed feedback through producer clocks remain combined tests.

## Host trace format

[trace.py](../../dv/system/trace.py) accepts UTF-8 JSONL with one version-one header:

```json
{"kind":"header","version":1,"bus_bytes":16,"ports":2,"capacity":64,"source":"actual_source_edge_adapter"}
```

All subsequent records have integer `ps` in simulator source-edge picoseconds, a `kind`, and exactly the fields below. Times are nondecreasing. Addresses/data/strobes/enables accept integers or base-prefixed numeric strings. Keys correlate observations; they are not expected data. Reset clears keys and increments the scoreboard epoch. A line is limited to 65536 characters, and a sampled instant to 4096 events.

| Kind | Required fields besides `kind`, `ps` |
| --- | --- |
| `aw`, `ar` | `key`, `port`, `id`, `address`, `length`, `size`, `burst`, `lock` |
| `w` | `port`, `data`, `strobe`, `last` |
| `pin` | `key`, `address`, `hex`, `enables`, `epoch` |
| `physical` | `key` |
| `integrity` | `key`, `failed` |
| `b` | `key`, `response`, `ready`, `posted` |
| `r` | `key`, `data`, `response`, `last`, `ready` |
| `fault` | No additional fields |
| `reset` | `destructive` |
| `end` | No additional fields |

`pin.hex` is ascending-address byte order, two hexadecimal digits per byte. Its enable bit zero selects the first byte. Physical events must come from the external memory/pin observer, not a DUT `done` flag. `b`/`r` describe every sampled VALID cycle, including repeated stalled payloads; `ready` records the actual handshake. Missing records cannot be inferred from a trace. End-of-trace rejects unsettled host counts and unresolved posted integrity. Separate WCK/CA, ECC, grant and lifecycle monitors must also finish; a host trace pass alone does not prove their behavior.

Replay an independently captured trace with:

```sh
PYTHONPATH=ips/lpddr5_mc/dv python3 -m system.trace \
  /absolute/path/to/trace.jsonl --report /absolute/path/to/new/trace-report.json
```

### Finite workload costs

After a nonbenchmark datapath/controller trace passes its owning checks, the integration runner adds a `workload_costs` report from [sampled source and pin observations](../../dv/integration/workload_costs.py). It records successful payload, transaction latency, response-backpressure samples and decoded command counts. Partial writes count only strobed bytes; narrow and unaligned reads count addressed bytes, excluding bus padding. Transactions with any failed response receive no payload credit. Handshakes, rather than repeated stalled VALID samples, earn credit. The shared rate interval starts at the first accepted address and ends at the last completed transaction; it includes source pacing, read/write interference, backpressure and intervening maintenance. Read and write rates use that same interval. A recovered clean trace gets a separate `recovered_workload_costs` report.

These finite-workload rates have no sustained benchmark threshold and do not isolate a feature's penalty without comparable controlled runs. Command counts cover the full observation interval, including idle maintenance before/after host traffic; they are not attributed stall cycles. Operational-reset traces need separate epoch segments, and this accountant rejects reset records. The focused accounting tests exercise partial/narrow transfers, error responses, repeated backpressure, ID reuse/out-of-order completion, command transitions and incomplete tails. The actual workload's data, protocol and configuration checks remain required.

The optional `start_ps`/`end_ps` arguments to [finite cost accounting](../../dv/integration/workload_costs.py) select a complete transaction interval from the original trace. Both boundaries must have no outstanding source transaction; crossing transactions, an uncovered end or an unsettled tail are rejected. Mode3 reports hot payload separately from the earlier normal-temperature/RFM phase, after independently completed MR4=13. Rates span the selected first admission through final completion and include pacing and interference; they have no same-rate benchmark promise or isolated thermal penalty interpretation.
