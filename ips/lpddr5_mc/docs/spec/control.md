# Configuration, lifecycle and recovery

The controller owns configuration admission and normal DRAM refresh. The PHY owns training algorithms and its DFI master windows. Software requests operations through APB mailboxes; it never becomes a second command writer. `configuration.py`, `lifecycle.py`, `update.py` and `dvfs.py` are executable reference contracts for the future RTL.

## APB4 and atomic publication

Use 32-bit APB4 data, byte-aligned PSTRB lanes, four-byte-aligned register addresses and an 18-bit local address window. Shared addresses are absolute; channel addresses add `0x10000 + channel*0x10000`. Unmapped, misaligned, locked, read-only writes, invalid broadcast and nonzero read strobes complete with PSLVERR and no side effects. Reserved bits read zero and ignore writes. An access has effects only once at PSEL/PENABLE/PREADY completion. PPROT is retained for diagnostics; this IP has no access-control firewall.

[registers.json](../../config/contracts/registers.json) owns widths, units, resets, access, locks and CDC metadata. [Generated register documentation](../programming/registers.md), SystemVerilog constants and C headers derive from it. `tools/generate.py --check` rejects stale products. RW configuration writes update staging state. The canonical [example](../../config/contracts/example.json) and [generated programming image](../../config/generated/example-register-image.json) provide a fully explicit integration fixture. `validate_register_image` deliberately admits exactly that supplied descriptor/profile, including independent pin checks, rather than certifying arbitrary software values.

MODE and regions require disabled traffic. Scheduler fields require quiescence. Inactive FSP banks may be edited while running, but publication and a frequency change require quiescence; editing an inactive bank does not alter live timing. Software sets FSP_VALID only for complete, qualified target images. Reset leaves all timing banks invalid and traffic disabled despite descriptive MODE defaults.

A commit freezes one immutable snapshot with a monotonically increasing 32-bit sequence. Every populated channel prepares and validates it, then the coordinator commits only after every channel acknowledges that exact sequence. No channel can observe a partially published image. A partial/stale acknowledgement cannot commit. Timeout/abort clears validity, disables admission and latches a fault. Independent AXI/APB resets fence old responses using an initialization/boot epoch; sequence wrap requires a fully drained coordinated reset. Mailbox sequence capacity is preflighted for the whole broadcast before any mutation.

CDC implementation must use request/acknowledgement toggles or equivalent proven asynchronous FIFOs, synchronized controls and stable bundled payloads held through acknowledgement. No independent synchronization of multi-bit values is allowed. AXI payloads/responses cross per-port asynchronous queues; backpressure reserves response capacity before acceptance. Reset assertion is asynchronous where required; deassertion is synchronized separately in each domain. Either endpoint reset invalidates outstanding CDC epochs and requires the fatal settlement/reinitialization path. The Python atomic protocol proves these semantics, not metastability or reset-domain implementation.

W1S fields are commands, read as zero and never retained as live levels. A shared command creates one coordinator mailbox entry; channel broadcast creates one per populated destination. DVFS.FSP is the next command's payload. CONTROL.BROADCAST selects channel broadcast only for channel-zero accesses; the bus decoder passes that choice explicitly to the register model. IRQ_STATUS is sticky W1C; IRQ_MASK gates the level interrupt. Configuration validity/trust is never cleared merely by acknowledging an interrupt. Hardware publishes RO/W1C status via coherent snapshots; only the hardware owner sets events. Performance snapshot captures both halves of all 64-bit saturating counters atomically. Error detail captures the first uncleared error; CE/UE counters continue saturating while later errors set an overflow event.

## Boot and training

Reset gives DFI ownership to the PHY, invalidates the profile, clears controller trust and increments the boot epoch on recovery. Initialization must establish the selected MR images, geometry/capability discovery, controller timing and external PHY training. The integration's PHY-independent boot coordinator observes dfi_init_complete, verifies the returned rank state is known IDLE or SELF_REFRESH, and requests software training completion with TRAIN_REQUEST and BOOT_EPOCH. Software writes TRAIN_TOKEN, then TRAIN_ACK.GO. Only a pending request with a matching token can set TRAIN_DONE; a stale high init_complete or old token is insufficient. Epoch zero is valid for the first boot.

The abstract `Lifecycle.boot` call represents completion of those prerequisites, including any required SRX/tXSR before handover. It requires the current training epoch, a qualified profile epoch, WCK disabled and a known state. It installs zero imported refresh debt/credit and a fresh refresh timestamp. Boot from self-refresh also records an extra-refresh-before-reentry obligation. INIT/ENABLE commands are separate: enabling requires controller ownership, trust, profile validity and no urgent maintenance. Missing training/profile data keeps admission disabled. The PHY boot timeout is explicit in each profile; timeout faults rather than fabricating completion.

## Refresh, thermal and RFM

Urgent refresh/thermal/RFM protection has priority over normal traffic, optional ZQ opportunities, power/DVFS requests and nonessential updates. Maintenance reserves its complete command, precharge, recovery and return budget before admission. Periodic REF is never postponed in the selected policy and low-temperature extended intervals are not used. REFpb advances the prescribed eight bank-pair sequence; only a full round discharges an all-bank obligation. Adjacent ACT pairs complete before preemption, so the next maintenance deadline must include that reservation.

MR4 codes 1–9 use no interval longer than the normal 3124 CK; codes 10–15 reduce it according to the standard's multiplier. Codes 0 or 16–31 fault. A thermal change invalidates old pull-in credit, exposes any newly overdue debt and blocks traffic until serviced. Codes 13/15 add conservative CK-rounded derating to core timings; the model adds 2 CK to RCD/RP/RAS and 3 to RC. Pin offset fixtures remain within the derated bounds. MR4 polling must meet the device's temperature reporting requirements; the fixture polls every 3000 CK. A missed retention deadline latches loss of trust.

Every admitted device supplies MR27/MR57. IMT is eight times MR27[5:1]; its multiplier is 2/4/6/8 from bits 7:6. ACT increments the bank-pair counter. At the maximum, another ACT is blocked until REF/RFM decrements it. REF subtracts IMT; RFM subtracts IMT times 1/1.5/2/4 from MR57[1:0], saturating at zero. Self-refresh preserves counters. RFM never substitutes for periodic REF. The selected paired-counter implementation does not claim a refresh-rate exemption or optional single-bank extensions.

Self-refresh entry requires the extra refresh after a preceding SRX, in addition to all ordinary REF obligations. Once SRE completes, DRAM self-refresh owns retention and a long hold can exceed tREFI. The long-hold model explicitly suspends external REF deadlines only for ranks in self-refresh. SRX waits at least tXSR=174 CK in these fixtures and starts fresh periodic timestamps, preserving the extra-before-reentry requirement. Normal power-down retains the external refresh deadline, so its duration is bounded by the remaining budget and tXP return time. A declined DFI low-power opportunity is normal; late/stuck acknowledgement or wakeup timeout faults.

MR28=0 uses background calibration; periodic ZQ latch is issued only without pending DQ and blocks subsequent data for tZQLAT. The fixture allows NZQ≤4, tZQCAL=1200 CK and tZQLAT=24 CK. ZQ or thermal handling cannot steal the last retention budget from REF.

## DFI management and FSP

A drained boundary includes all host responses, true final pin writes and twrdata_delay, link write-epoch results, split reads, dirty inline check data and correction scrubs. It requires WCK fully disabled, closed pages where required and reserved refresh return time. An empty command queue alone never means drained.

For controller update with minimum m and maximum M, request edge zero asserts after the edge. A responding PHY asserts acknowledgement at sampled edge `1 <= a < m`, deasserts at `a < b <= M-2`, and request releases after `max(m,b+1)`. With no acknowledgement, release is after m. Profiles require m≥2 and M≥m+2. The selected fixture uses m=4/M=32. Boundary/late/unsolicited/stuck/reasserted acknowledgement faults; timer expiry never establishes ownership. Before the request, remaining retention must cover maximum pause plus return. A competing PHY update waits for registered controller release and completes within the original tphyupd_resp deadline.

PHY updates reserve response/type-specific maximum time, drain writes and disable WCK before acknowledgement. Runtime PHY-master entry closes every active rank's pages and honors the stable syscs_state, CS-state choice and state_sel. The MC remains the sole refresh requester in IDLE; the PHY executes each request within tphymstr_rfsh, with no normal ACT/PRE injected by the MC. Ranks placed in self-refresh need no external REF during the window. Type timeout or unknown returned state is ownership loss. The integration must attest the same known rank states at return before fresh WCK synchronization.

For FSP, prepare all target MR/timing/training images while inactive, drain, WS_OFF and disable WCK, program FSP-WR and target MRs, switch FSP-OP, observe the conservative 201-CK long guard and six running CK on each clock boundary, complete target training, then atomically publish its profile epoch. DFI uses low-then-high init_complete: a fresh low strictly before tinit_start accepts the request; unchanged high is a decline. Frequency/ratio/FSP remain stable during the request, no clock change precedes acceptance, and release is registered before a later completion high. tinit_complete bounds return. Decline keeps the old epoch. The digital fixtures qualify WCK-ratio/FSP changes at constant CK; arbitrary CK rates and voltage ramps need separately qualified timing profiles and power integration.

## Failure and destructive recovery

Any protocol, ownership or retention failure stops new AW/AR and ordinary DRAM issue, records sticky fault/trust status and holds DFI in its known safe state. Unknown ownership remains UNKNOWN. Already accepted reads return all remaining beats with their original IDs/counts/RLAST and SLVERR (zero data); writes consume all remaining W beats in AW order and return one B error after settlement. Previously delivered beats and posted B responses cannot be retracted. Existing DECERR remains DECERR. Software must not infer rollback of completed physical writes.

Recovery requires host settlement or an explicitly coordinated host reset, then destructive DRAM/controller reset, dirty/cache/tracking invalidation, a new boot/training epoch and complete reinitialization. Memory contents are untrusted and must be reestablished before reuse. Clearing IRQ_STATUS, timer expiry, dfi_error alone or a stale completion level never permits automatic resume. The host, integrity and lifecycle models test these boundaries independently; later RTL integration must connect all three owners.

## Status and policy encodings

STATUS.STATE is 0 RESET,1 QUIESCED,2 RUN,3 TRANSFER,4 SELF_REFRESH,5 FAULT; other values are reserved. TRAIN_REQUEST/TRAIN_DONE are single-bit hardware states. BOOT_EPOCH and CONFIG_EPOCH are full 32-bit values. TRAIN_ACK never writes TRAIN_DONE directly.

ERROR_ADDR_LO/HI retain the complete 40-bit address (HI uses its low eight bits); ERROR_AXI_ID retains 16 bits and ERROR_TAG_LO/HI retain 64. ERROR_INFO uses syndrome[8:0], correlated bit9, uncorrectable bit10, trusted bit11, port bit12, rank bit13 and operation[17:14]; remaining bits read zero. The channel is identified by the channel register window. IRQ event bits 0–12 are initialization complete, training request, configuration committed, quiesced, DVFS complete, corrected ECC, uncorrectable ECC, posted late error, thermal change, DFI fault, retention loss, detail overflow and configuration fault. Bits13–31 are reserved. A new error preserves the first uncleared detail; clearing the error event arms the next capture. Reading diagnostic registers has no clear side effect.

PM_REQUEST0 is disabled,1 power-down opportunity,2 self-refresh opportunity; other values reject activation. Zero PD_IDLE/SR_IDLE disables the corresponding automatic opportunity. BW_MODE0/1 means strict/work-conserving;2/3 reject activation. AGE_STEP is one in the qualified integration descriptor; AGE_TICK_DIV is positive. WR_LOW≤WR_HIGH≤queue depth, batch minima≤batch maximum and every port outstanding limit≤its allocated credits. The generated example derives watermarks/limits from queue capacity and uses 64-byte cap charging. The implementation must reject invalid complete snapshots before any channel commits them.
