# AXI ordering and data integrity

`host.py` defines transaction-level AXI behavior; `integrity.py`, the standard link matrices and independent completion oracles define data lifetimes. These are contracts and executable references for later frontend/channel RTL. Arm protocol identities are in [reference-sources.json](../../config/reference/reference-sources.json).

## AXI admission and responses

Accept INCR up to 256 beats, FIXED up to 16, WRAP of 2/4/8/16 beats, and narrow/unaligned accesses within the active 64/128/256-bit bus. WRAP starts must be transfer aligned. No burst crosses 4 KB or the configured address width. Invalid or unmapped requests produce complete DECERR sequences and no memory effects. Malformed strobes/WLAST on a decoded write produce SLVERR after consuming the admitted beat count. No error response truncates an accepted read or invents an extra B. Wrong WLAST is a host protocol violation; the error path does not treat an early WLAST as permission to lose remaining accepted data.

Global admission order is sampled AXI acceptance order; at an arbitration tie use port zero before one, AW before AR within a port. A full AW byte-range hazard exists before W arrives. AXI4 W has no ID and is associated with AW in order per port. Buffer the complete write and validate all beats before any memory effect. Reads/writes touching any older unfinished overlapping byte range wait; nonoverlapping requests can proceed. Same-ID responses remain ordered separately for reads and writes on each port. IDs on different ports are distinct.

An unsupported exclusive monitor accepts AxLOCK with ordinary memory effects and OKAY, never EXOKAY, as permitted for an AXI slave without exclusive support. AxCACHE/AxPROT are diagnostic attributes; no coherency/security service is implied. AXI USER and AXI5 extensions are outside this interface.

The serial reference oracle establishes the observable result for frontend forwarding and merging. Forwarding overlays every older fully buffered overlapping write in admission order, byte by byte, on committed memory. It records dependencies on all contributing writes; the read cannot retire successfully before those writes' integrity outcomes are known. An uncorrectable/failed dependency fails the forwarded read. Unreceived W data cannot be forwarded. A merge may combine compatible granules only with no intervening older overlapping read, identical region/rank/ECC/profile epoch and a separately retained response dependency for every original transaction. Failed/deferred response dependencies retain their buffers. These implementation optimizations must match the serial oracle, preserve ECC locks/versions and cannot move a B before the applicable commit rule.

Read tracking retains tag, profile epoch, word index, byte slice and split half. A byte slice contributes 16 bits per DFI word. Each slice has independent valid/gaps/rotation; DNV consumes the word but marks unavailable bytes. A request completes only after every required word and slice, including both BL32 halves. Response storage remains reserved through the final AXI handshake. Initialization, init_start and selected update events reset the word pointer only after drain or explicit fatal abortion.

## Regions and reserved capacity

Configuration permits up to eight nonoverlapping, page-aligned power-of-two regions. Each has an explicit invertible bit permutation, preserving its low six byte/granule bits. Sort regions by base, pack their mapped offsets into consecutive physical storage, then stripe bit six across two channels when enabled. Remove that channel bit before decoding local geometry: byte bits 0–10, bank bits 11–14, 15 row bits above that, and rank by one-GiB capacity. `decode_address` is the executable geometry contract. Region holes produce DECERR; aggregate capacity cannot exceed discovered ranks/channels. The permutation cannot alias addresses or silently wrap rows.

For inline ECC, each rank's available protected data is `floor(physical_bytes/576)*512`; the remaining 64 bytes per full 576-byte allocation group hold one check byte per protected 8-byte word. Data is packed before the check area. Logical word w maps to data offset 8w and check offset `data_bytes+w`; any incomplete final allocation group is unavailable. Channel striping precedes rank selection using that reduced capacity. The software-visible regions expose only protected data; reserved checks are never accessible as ordinary host memory.

## Link ECC transport

The controller owns link encoding and decoding. For each byte lane and 16-beat group it protects 128 data bits; writes additionally protect sixteen DMI bits. BL32 has two independent code sets per byte, retaining original beat identities across the split gap. Source matrices are JESD209-5C Tables 331/332. The matrix decoder checks syndrome columns independently of any future RTL implementation. Tests exhaust every single and double codeword fault and seeded payloads; triple-error correction is not promised.

Write parity is carried on raw RDQS_t: beat zero reserved, beats 1–6 DMI C0–C5, beats 7–15 data C0–C8. Read parity is raw DMI on beats 7–15, with earlier parity positions reserved. The PHY must expose pin-order data and this parity without silently applying its own link correction/DBI. `link_parity` in the canonical DFI payloads is an explicit integration extension; generic dfi_error does not provide this transport. No raw extension or no discovered DRAM support means link mode is rejected. It is deliberately unavailable at ratio two.

MWR supports only BL16 in the admitted BG/16B modes (JEDEC 7.4.9/Table 231). Split a partially masked 64-byte logical granule into two MWR16 commands, preserving their shared host tag and separate group identities. Enforce tCCDMW: sixteen CK to the same bank, four CK to a different bank in the same BG (or any different bank at ratio two), two CK across BGs. `transport` represents the logical per-group bits; it does not assert that a masked BL32 physical command exists. The command packer rejects that command.

Apply write mask/DBI first, then protect transmitted DQ/DMI and generate link parity. With DBI, invert a byte when it has more than four ones and drive DMI high. Combined masked-write/DBI uses DQ=0xFC,DMI=0 as the masked marker. On receive correct link data and DMI before interpreting mask or reversing DBI. Read link conflicts with read DBI and data-copy modes. An uncorrectable block produces a correlated read error; unavailable words never become successful data.

## Write acknowledgement and inline ECC

Default strict write-link mode groups at most sixteen writes in a rank's epoch, stops admission, drains actual pin writes and polls MR43 within 256 CK of its first write. Observe the MR43 read/clear interval of at least tMRR+tMRW before reopening. Any reported write-link failure marks every write in that epoch SLVERR because MR43 is not per-transaction. No B precedes the epoch result. Posted mode may make OKAY eligible only at or after the protected physical write's completion edge. Eligibility is separate from asserting BVALID and from the BVALID/BREADY handshake. An MR43 failure or ownership loss changes every unoffered response to SLVERR, including a physically complete posted write whose B was not offered. An already offered B remains stable through backpressure; an acknowledged B cannot be retracted. Exposed posted OKAY followed by a failure sets the sticky uncorrelated late-error indication. Physical completion alone never counts as acknowledgement or removes response storage.

`WriteEpoch.add(tag, at, pin_end)` admits a physical-completion witness without exposing an early response. `advance(at)` samples completed witnesses; posted eligibility appears at `pin_end`, while strict eligibility waits for MR43 settlement. `offer(tag, at)` records BVALID, and `acknowledge(tag, at)` records the actual handshake (it may offer on the same edge). The `responses`, `offered` and `acknowledged` maps represent these distinct states. `settle` returns per-tag integrity outcomes, including already acknowledged tags, rather than new bus handshakes. `fail(at)` fails unoffered responses, preserves offered values, closes the epoch and blocks new admission; omitting its time means the current sampled edge. Recovery creates a fresh owner only after settling the old host responses. Clock progression is monotonic; polling cannot precede the last physical completion, repeat or reopen admission before the read/clear guard.

Inline SECDED is the controller's explicit layout: Hamming positions 1–71, check positions at powers of two and overall even parity at position 72. Check-byte bits 0–6 hold parity positions 1/2/4/8/16/32/64; bit 7 holds overall position 72. Single errors are corrected/reported, doubles are uncorrectable. This format is independent of the DRAM's link code.

A partial inline write locks its protected 8-byte word, reads/corrects old data, merges enabled bytes, regenerates its check byte and keeps the lock until both physical data and check writes complete. The ECC cache reserves the corresponding 64-byte check line; dirty lines cannot be evicted to create credits. Separate word updates sharing a check line must serialize physical check-byte merges so no byte is lost. The reference `InlineStore` models atomic word/check commit and dirty-line occupancy, rather than an actual DRAM cache implementation.

A correction schedules a scrub with the observed word version. A newer host write invalidates the stale scrub; a locked word defers it. A failed physical data/check pair poisons that word because DRAM writes are not atomic. Reads/partial overwrites then fail until a successful full rewrite or destructive recovery. Quiesce waits for pending data/check writes, dirty lines, locks and scrub work. A normal reset is rejected while these remain; destructive recovery explicitly loses trust. Inline-plus-link performs inline encoding first, then link encoding on each physical data/check transfer; decode reverses that order. The throughput benchmark disables both because these extra transactions and strict polling require separate measured workloads.
